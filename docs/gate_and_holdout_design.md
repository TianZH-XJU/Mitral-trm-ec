# Gate 与新保留集设计（v0.3，2026-10-25——仅设计+数据审计，不训练）

按阶段九审核修订。**关键新信息：模板分组数据审计（§1.3）发现了结构性障碍，本版提出两个候选方案供审核裁决，在裁决前不冻结任何划分。**

## 1. 分组键的纯数据审计（只读，已完成）

### 1.1 可复算分组键（不再依赖句首大小写）

- **专名集合**：token 首字母大写且（非句首 或 句首但不属于功能词 a/the/an/some）——句首的 A/The 排除，专名识别不依赖位置。
- **动词集合**：从目标逻辑形式中提取（`<词> . <关系>` 模式中点号前的词）——COGS 官方生成语法可复算。
- **功能词表**：封闭枚举（a/the/an/and/or/that/was/were/to/by/of/in/on/beside/behind/./'s/is/did/do/does/n’t/not）。
- **模板键 v1（结构骨架）**：专名→`<ARG>`、普通名词→`<ARG>`、动词保留、功能词保留。

### 1.3 结构性障碍（如实报告，v0.2 方案不可直接执行）

**问题**：COGS 的句子由封闭语法生成，实体/名词组合近乎唯一——按结构模板分组后 85% 的组只有 1 个样本。后果：
1. gate 三组（~2,000–3,200 样本）虽然够用，但**组级 bootstrap 的重采样单元（模板组）大量为单例**——组数 12,269 中单例占绝对多数，"按模板组 bootstrap"退化为近似逐样本 bootstrap，审查要求的组内相关性校正几乎失效；
2. 更本质的：**分区之间零模板重叠**意味着 gate-confirm 上评估的是"未见句法结构"的外推，而 gate 训练/验证分布与之不同——这不是泄漏问题，而是 gate 特征的分布漂移问题，与 v0.2 想解决的分布不匹配是同族风险。

### 1.4 两个候选方案（供审核裁决）

**方案 S1（模板组划分 + 如实接受外推设定）**：保持 1.1 分组与 70/10/10/10；bootstrap 单元改用"动词骨架组"（同主动词+语态的粗组，~数百个，非单例）做重采样，模板组仅用于划分隔离。gate-confirm 上的结论明确定位为"未见模板上的 gate 泛化"。风险：若 gate 依赖模板特定模式，confirm 表现将系统性偏低。
**方案 S2（实例级划分 + 嵌套验证）**：放弃按模板分组，按**样本行**划分 70/10/10/10（固定种子）；接受"同一模板可能跨分区"的轻度泄漏风险，但用**嵌套验证**补偿：gate-confirm 的 bootstrap 按模板组聚合报告，并在报告时明确该泄漏边界。优点：三组分布一致、bootstrap 语义清晰；缺点：结构模板跨组（gate 可能记忆模板→confirm 乐观）。
**方案 S3（折中，备选）**：按"动词骨架"粗组（非单例、数百组）划分 70/10/10/10——隔离粒度介于两者之间，组数足以支撑组级 bootstrap，同一骨架下不同细节模板仍可能跨组（与 S2 同样的轻度泄漏，但骨架级隔离防住最大的结构泄漏源）。

**裁决前不冻结划分；三个方案的划分脚本都尚未运行（1.2 的数字来自审计性模拟，未持久化）。**

## 2. 执行语义与成本（v0.3 按审核公式收紧）

决策流程：e0 生成（L0 个 token）→ gate 决策 1 → 若继续：e1 生成（L1）→ gate 决策 2 → 若继续：e3 生成（L3）。

成本分别记录（r 为实际执行的生成轮次，e_r 为该轮 extra_loops）：
- **N_tokens = Σ_r L_r**（重复生成的总 token 数）
- **N_cell = Σ_r L_r × (1 + e_r)**（递归单元调用数的简化计数；实现中如有其他重复调用按实际记录补充）
- **gate 前向开销**（两个决策点合计的 gate 特征计算 + 逻辑回归前向，按秒）
- **端到端 CPU 推理时间**（实测秒数）
- 报告：N_tokens、N_cell、gate 开销、端到端时间四列并列；Pareto 主轴用 N_cell（计算成本的主要成分），N_tokens 与时间作为次轴。

## 3. 目标 A 的 Oracle 标签与动作映射（v0.3 冻结）

- **Oracle 深度**：候选 {0,1,3} 中若有深度得到正确完整序列 → 取**最浅的正确深度**；若全部错误 → 取 e0（成本最低）。该 Oracle 优化"先正确、再最小计算"。
- **动作映射（预注册，二选一待裁决）**：(a) 两个独立二分类决策器（决策点 1：e0→e1；决策点 2：e1→e3），各自从 Oracle 深度导出标签（d*≤0→停；否则继续 / d*≤1→停；否则继续）；(b) 单个三分类深度预测器（d*∈{0,1,3}）再映射为动作。**默认 (a)**（两个决策点特征不同，独立训练更自然；(b) 作为对照实现）。
- 推理时 gate 只用模型内部特征（无 gold）；Oracle 仅用于监督标签。
- 若需覆盖更多准确率-成本权衡点 → 另行预注册（如 λ 加权目标），不得结果后临时改。

## 4. 目标 B：**从实施清单移除**

按审核指出的根本问题：共同前缀内的 token 两深度本就相同，无法从中识别修复/破坏——前缀对齐规则正确但标签无信息量。目标 B 降级为未来独立方法分支：若研究 token 级 gate，应在**同一参考前缀**（由参考策略生成的自由解码前缀）上分别计算不同深度的下一 token 预测，以真实 token 构造局部反事实标签；最终策略仍须真实自回归评估。当前阶段只做目标 A。

## 5. 对照与统计判据（v0.3 收紧）

对照（gate-confirm 一次性评估）：固定 e0 / e1 / e3、阈值 gate、逻辑回归 gate。
- **最优固定深度的选择**：在 gate-validation 上选定并冻结（e0/e1/e3 三者中 EM 最高者；若并列取成本低者），不得看 gate-confirm 后再挑。
- **成功标准（预注册）**：
  - 路径 1（省算）：EM 差（gate − 最优固定深度）的按组配对 bootstrap 95% CI 完全 ≥ −0.5pp，且 N_cell 减少 ≥30%；
  - 路径 2（提准）：**在 N_cell 不增加（≤ 最优固定深度的 N_cell）的预算约束下**，EM 差 CI 完全 ≥ +1pp。
- **bootstrap 单元**：按 1.4 裁决的分组方案的组（S1/S3 为骨架组）；报告 confirm 集的独立组数量；对 EM 差与 N_cell 差均报告区间。
- **不确定与证据不足**：CI 同时容许 ±1pp → 不确定；破坏类事件（训练标签中全错深度被选中的反例）<100/种子 → 证据不足；组数不足以支撑稳定估计 → 如实报告而非宣称可靠。
