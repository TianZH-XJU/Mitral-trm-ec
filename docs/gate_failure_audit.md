# Gate 失败审计（任务 01，2026-10-26——只读现有轨迹与结果，无新训练）

## 核心结论：**无实现错误、无数据流缺陷——是真实的策略失败**，但根源是**类别失衡 + 信号信息量不足**，而非 Logistic Regression 优化方式不当。

## 1. `g2_train_n = 0` 之谜（R2 三个种子）

**确认原因：真实的类别极不平衡，非构造缺陷。**

R2 的 Gate1 oracle 标签分布（gate_train）：

| 配置 | oracle=0（e0 已对，应停） | oracle≥1（应继续） | 占比 |
|---|---|---|---|
| R2_s0 | 2,232 | 185 | 继续仅 **7.7%** |
| R2_s1 | 2,283 | 134 | **5.5%** |
| R2_s2 | 2,181 | 236 | **9.8%** |

组均衡逻辑回归在 6 维特征上学到的是**多数类基线**（"总停"）：训练内继续率 = OOF 继续率 = validation 继续率 = **0.000**（分类 acc 90–95% 完全由多数类贡献）。因此 Gate2 的训练集（= Gate1 OOF 判继续的样本）为空，`g2_train_n=0`。**OOF 交叉拟合本身实现正确**——空集是该策略在该特征空间上的真实行为，不是代码缺陷。

**重要的下游影响**：R2 的"gate"实际上是"永远停在 e0"策略（Gate2 从未训练也从未被调用）。因此 R2 的确认集结果（EM 91.8–92.9% vs 固定 e3 的 95.4–96.7%）就是 **固定 e0 基线** 的表现——R2 的 gate 实验等价于"e0 vs 最优固定深度"的比较，Gate2 的"省算但损准"解读在 R2 上不成立，需要修正为：**R2 的失败 = 总停在 e0**。

## 2. R1 的行为：几乎总继续（非"过度继续"——是 oracle 决定的）

R1 的 oracle 分布（gate_train）：oracle≥1 占 **92.5–96.6%**（e0 EM=0%，final-only 监督下 e0 几乎全错）。Gate1 学到"总继续"（继续率 99.8–100%），与多数类基线一致。**这不是 gate 误判——oracle 本身就该继续**。R1 的失败发生在 Gate2：总继续到 e3 的 N_cell（~920）高于固定 e3（~390）是因为**两阶段成本计算正确地包含了 e0+e1 两轮前缀生成**（协议规定成本全计），EM 却因 Gate2 在部分样本上停在 e1（错误层）而低于固定 e3。**成本核算与协议一致，无错**。

## 4. AUC 诊断（信号信息量的初步证据）

Gate1 在 validation 上的 AUC（正类=继续）：

| 配置 | AUC | 说明 |
|---|---|---|
| R1_s0 | 0.712 | 有一定信息 |
| R1_s1 | **0.495** | 等同随机 |
| R1_s2 | 0.835 | 有信息 |
| R2_s0 | 0.564 | 弱 |
| R2_s1 | 0.569 | 弱 |
| R2_s2 | 0.513 | 随机 |

**跨种子不稳定（0.49–0.84）**——与 SCAN 上的信号分析（0.28–0.88）一致的复现。这是任务 02 信号诊断的核心预告：特征信息量存在但不稳定。

## 5. 判定（按审核的分支规则）

- **非**实现错误/数据流问题（无修复项）；
- **是**真实的策略失败，根源为：(a) 类别极度失衡（R2 继续 5–10%；R1 停止 3–7%），组均衡逻辑回归退化为多数类基线；(b) 信号跨种子不稳定（AUC 0.49–0.84）。
- **对 CMA-ES 的预判**（待任务 02 确认）：类别失衡是标签问题不是优化器问题——CMA-ES 若直接以 EM+成本为适应度（离散、非 oracle 标签），可绕开失衡标签问题，但**若特征本身信息量不足，优化器更换无法解决**（审核的"不要继续搜索同一组参数"分支风险）。任务 02 的信号增益分析是 CMA-ES 是否值得跑的决定性证据。
- R2 结果解读修正：其 gate 实验 = e0 固定基线（Gate2 从未被训练/调用），报告中已如实标注。
