# 03C-1 跟进审计：Gate2 候选匹配与 CI 可复现性

日期：2026-10-27  
审计对象：`scripts/gate_threshold_baseline.py`、`runs/gate_exp/gate_03c1/r2_threshold_baseline.json`、`docs/gate_threshold_baseline_report.md`、提交 `6bfb1e5`

## 裁决

**暂缓批准 CMA-ES；先修正并重跑 03C-1 的开发评估。** 这不否定目前的方向性结果。修正后 R2 的类加权策略在两个 seed 上出现较大的开发集计算节省，但当前实现尚不足以证明这些候选是公平、可复现的强基线。

## 阻塞项 1：Gate2 未与每个 Gate1 候选配对

当前脚本先从 Gate1 的 OOF 汇总中选出一个 `best_pw`（结果为 pw=16），再用该配置在阈值 0.5 下的 OOF 继续样本训练一个 Gate2。随后，脚本把**同一个 Gate2**用于全部 `pw × tau` 候选，包括报告中的 `lr_pw8_tau0.3`。因此：

- Gate2 训练样本由 pw=16、tau=0.5 的 OOF 动作决定；
- 被评估候选的 Gate1 却可能是 pw=8、tau=0.3 等不同动作规则；
- 继续到 e1/e3 的训练分布与候选实际送达 Gate2 的分布不匹配。

这违反了“Gate2 只使用与该 Gate1 策略相匹配的组级 OOF 继续轨迹”的实验要求，并可能影响 EM 与成本。当前候选排名须标记为**暂定**。

### 修复要求

1. 对每一个预注册的 Gate1 配置 `(pw, tau)`，在 `gate_train` 上基于组级 K=5 OOF 分数生成该配置的继续动作。
2. 使用该配置自己的 OOF 继续样本训练对应 Gate2；目标仍按冻结 oracle 定义，权重仍按组均衡规范执行。
3. 在 validation 上只评估与该配置配对的 Gate2，不允许复用其他 Gate1 设置下的 Gate2。
4. 如果候选的继续样本数不足或 Gate2 目标只有单一类别，明确记录“该配置 Gate2 不可拟合”，按预先固定的 fallback 规则处理或将候选标为不可比较；不得静默复用另一个候选的 Gate2。
5. entropy/n_gen 单信号候选同样需要与其自身的 OOF 继续路由配对；或者把它们明确限定为“一阶段 e0→e3”透明基线，不能将其报告成未经匹配的两阶段 Gate。
6. 保存每个候选的 Gate1 OOF 继续率、Gate2 训练样本数/正类数、validation 动作深度及逐样本 EM/`N_tokens`/`N_cell`。

## 阻塞项 2：95% group-bootstrap CI 未由已提交产物复现

`gate_threshold_baseline.py` 定义了 `group_bootstrap_ci`，但脚本中没有调用该函数；`r2_threshold_baseline.json` 中只保存候选聚合指标，没有 EM 差的 CI 字段。报告声称已计算 bootstrap CI，却没有给出区间端点或可复算的明细。因此这项判定尚未被已提交工件证明。

### 修复要求

1. 对冻结深度与每个配对候选，在相同样本上计算逐样本 EM 差。
2. 按冻结的 group key 进行配对 group bootstrap，并实际调用函数输出 95% CI 两端点；固定随机种子与重复次数。
3. 在 JSON 中保存候选配置、点估计、区间、成本差、成本降幅、重采样参数及样本/组数量；同时保存足以复算上述数字的逐样本日志。
4. 不得只以 EM 点估计在 -0.5pp 内就判定效率路径满足；如报告路径判定，必须展示所要求的 CI 下界。
5. 因 validation 已被用于选择策略，validation bootstrap 区间属于**开发/选择后诊断**，不能当作独立确认性区间，也不能单独支持泛化成功的声明。

## 03C-1 修订执行范围

- 不重训 R2 或其他基础模型。
- 使用相同的 `traj_v2/gate_train` 与 `traj_v2/gate_validation`，只修正 Gate2 配对、记录与统计流程；旧结果保留，新增独立版本目录/文件，不覆盖历史日志。
- 按预先固定的候选集合 `pw ∈ {1,2,4,8,16}`、`tau ∈ {0.02,0.05,0.1,0.2,0.3,0.5,0.7}` 完成配对评估；若为单信号基线，预先定义其阈值候选与一阶段/两阶段语义。
- 固定深度 baseline 仍由同一修正轨迹逐样本成本计算；每个 seed 分别按 validation EM 主序、成本次序选择固定深度。
- 结果必须说明候选选择规则、候选数、seed 级结果及组平衡结果。Validation 用于这次修订开发后，所有结论仍属探索性开发证据。
