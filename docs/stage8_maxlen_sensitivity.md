# 阶段八：max_len=400 长度敏感性分析（探索性，2026-10-25）

范围（审核批准）：仅 cp_recursion / pp_recursion；既有 R1/R2 checkpoint（探索性复现版，bit-exact）；seed 0/1/2；extra 0/3；max_len=400；无训练。结果独立存放（`results/cogs_maxlen400_sensitivity.csv`、`runs/cogs/maxlen400/`），不覆盖 max_len=200 主结果，不与 E0/E0W 做参数匹配比较（无对应长上限 checkpoint）。

## 结果（每格为该类 1,000 样本）

**全部 24 个 (模型×种子×深度×类别) 配置中，EM400=0 的有 23 个；唯一非零：R2_s1@e3 pp_recursion = 0.1%（1/1000）。**

| 条件 | cp_recursion EM400 | pp_recursion EM400 |
|---|---|---|
| R1@e0（3 种子） | 0 / 0 / 0 | 0 / 0 / 0 |
| R1@e3（3 种子） | 0 / 0 / 0 | 0 / 0 / 0 |
| R2@e0（3 种子） | 0 / 0 / 0 | 0 / 0 / 0 |
| R2@e3（3 种子） | 0 / 0 / 0 | **0.1%** / 0 / 0 |

EOS 终止（max_len=400 下）：多数配置 >60% 样本正常生成 EOS（如 R2_s0@e3 cp 99.2%、R1_s1@e0 cp 95.7%），即模型**能输出完整长度的形式**——失败不是"写不完"，而是内容错误。hit400（仍触上限）在 R1@e3 上反而高于 @e0（441 vs 165 等），说明深层递归在错误轨道上生成更长但不正确的输出。

## 结论

1. **解码预算不是 cp/pp_recursion 失败的主因**：上限从 200 提到 400（覆盖最长 341-token gold），EM 几乎完全不变（0→0）。此前长度审计的"66.7%/54.3% gold 超限"混杂，实际影响方向是：即使可以写完，模型也写不对。
2. 结合阶段七类型学（变量索引错误为主导标签），cp/pp_recursion 的失败模式与 obj_pp_to_subj_pp 一致：**变量索引跟踪**。三类结构泛化失败现在可以统一表述为同一机制假设（在当前隐式递归架构下）。
3. 定位：探索性敏感性分析（gen 已解封后的诊断），写入论文"机制诊断"节，不改变主结果。
